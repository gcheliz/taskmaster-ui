# Task ID: 61
# Title: Page Implementation: Repository Management Interface
# Status: done
# Dependencies: 52, 55, 60
# Priority: medium
# Description: Create a comprehensive Git repository management interface featuring a repository overview, connection status, detailed Git statistics, branch status indicators, health monitoring, and quick actions for common Git operations.
# Details:
Implement the repository management page based on the provided HTML mockups. The page will display a collection of 'Repository Cards', each representing a connected Git repository. 

1.  **Component Development:** Utilize the atomic components from Task #52 to construct the page. The primary component will be a 'RepositoryCard' molecule/organism.
2.  **Repository Card Structure:**
    *   **Header:** Display the repository name and a connection status badge ('Connected', 'Error', 'Syncing').
    *   **Git Statistics:** Fetch and display key metrics like total commits, number of branches, and open pull requests, using icons for visual clarity.
    *   **Branch Status:** List primary branches (e.g., main, develop) with color-coded status indicators (e.g., green for up-to-date, yellow for ahead/behind, red for conflict).
    *   **Repository Health:** Implement a visual health score/indicator based on metrics like branch staleness, PR age, and commit frequency.
    *   **Quick Actions:** Include a button group for 'Sync', 'New Branch' (triggering a modal), and 'View Commits'.
3.  **API Integration:** Connect the frontend to the Git API endpoints established in Task #55. Use a data-fetching library like SWR or React Query to handle asynchronous operations, caching, and real-time updates (via polling or re-fetch on focus).
4.  **State Management:** Employ a centralized state management solution (e.g., Zustand, Redux Toolkit) to manage the list of repositories, their individual states (loading, error, data), and the UI state for modals and forms.

# Test Strategy:
1.  **Unit Tests (Jest/Vitest + React Testing Library):**
    *   Test the `RepositoryCard` component with mocked props for all possible states (e.g., different connection statuses, branch health indicators) to verify correct rendering.
    *   Unit test the logic for determining branch status colors and repository health scores.
    *   Test form validation and submission logic within the 'New Branch' modal.
2.  **Integration Tests (Mock Service Worker):**
    *   Mock the Git API to simulate various scenarios, including successful data fetching, API errors, and empty states.
    *   Verify that the page correctly renders a list of repositories from the mocked API.
    *   Test that clicking 'Sync' or other quick actions triggers the correct API requests with appropriate payloads.
3.  **End-to-End Tests (Cypress/Playwright):**
    *   Create a test workflow that navigates to the page, asserts that repository cards are visible and contain data.
    *   Simulate user interaction with quick actions, such as filling out and submitting the 'New Branch' form, and verify the UI updates accordingly.
4.  **Visual Regression Testing (Chromatic/Percy):**
    *   Capture and approve snapshots of the `RepositoryCard` component and the full page layout in various states to prevent unintended UI changes.
