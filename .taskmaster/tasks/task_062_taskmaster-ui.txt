# Task ID: 62
# Title: Page Implementation: Terminal Interface
# Status: done
# Dependencies: 52, 58, 60
# Priority: medium
# Description: Create an embedded terminal interface that integrates with the TaskMaster CLI, providing authentic terminal aesthetics, command history, shortcuts, and real-time command execution based on the provided mockups.
# Details:
Implement the embedded terminal page using `xterm.js` for core terminal emulation and WebSockets for real-time communication with the backend TaskMaster CLI process.

1.  **Technology Selection:**
    *   Utilize `xterm.js` as the core library for rendering the terminal UI.
    *   Use the `xterm-addon-fit` to make the terminal responsive to its container size.
    *   Implement a WebSocket connection (`ws` or `socket.io`) to handle the real-time, bidirectional communication between the client and the server-side CLI process.

2.  **Component Development:**
    *   Create a `Terminal` organism component that encapsulates the `xterm.js` instance and its lifecycle (initialization, connection, disposal).
    *   This component will manage the WebSocket connection, sending user input and receiving command output.
    *   Use atomic components from Task #52 for any surrounding UI elements like session tabs or control buttons.

3.  **Feature Implementation:**
    *   **Authentic Aesthetics:** Configure `xterm.js` with a custom theme (colors, font, font size) to match the project's dark theme (Task #52) and the HTML mockups. Implement a blinking block cursor for an authentic feel.
    *   **CLI Integration:** On component mount, establish a WebSocket connection. User input (ending with the Enter key) is sent over the socket. Data received from the socket is written directly to the `xterm.js` instance.
    *   **Command History:** Implement a client-side buffer to store a history of executed commands. Handle the Up and Down arrow key presses to navigate this history and populate the input line.
    *   **Quick Command Shortcuts:** Implement key bindings for common actions. Use `xterm.js`'s `onKey` event handler to capture key presses for shortcuts like `Ctrl+L` (clear screen) and `Ctrl+C` (send interrupt signal over WebSocket).
    *   **Session Management:** The parent component should manage an array of active terminal sessions. Each session will have its own `Terminal` component instance and a corresponding WebSocket connection. Implement a tabbed interface to switch between sessions.

# Test Strategy:
1.  **Unit Tests (Jest/Vitest + React Testing Library):**
    *   Test the `Terminal` component by mocking the `xterm.js` library and the WebSocket API.
    *   Verify that the component correctly initializes `xterm.js` on mount.
    *   Simulate user key presses and assert that commands are sent through the mocked WebSocket.
    *   Simulate receiving messages from the mocked WebSocket and assert that the `xterm.write` method is called with the correct data.
    *   Unit test the command history logic: adding new commands, preventing duplicates, and navigating with arrow keys.

2.  **Integration Tests (Cypress/Playwright):**
    *   Create tests against a mocked WebSocket server that echoes commands or returns predefined responses.
    *   Write a test that types a command, presses Enter, and verifies that the expected response from the mock server is rendered in the terminal.
    *   Test keyboard shortcuts like `Ctrl+L` to ensure the terminal view is cleared.

3.  **End-to-End Tests:**
    *   Run a test against a live development server. Execute a simple, non-destructive CLI command (e.g., `help`, `--version`) and validate that the output is correct and properly formatted.

4.  **Visual Regression Testing:**
    *   Create a Storybook story for the `Terminal` component. Use Chromatic or a similar tool to capture snapshots and prevent unintended visual changes to the terminal's theme, cursor, and font.

# Subtasks:
## 1. Terminal Component Scaffolding and WebSocket Connection [done]
### Dependencies: None
### Description: Create the foundational `Terminal` organism component. This subtask focuses on initializing an `xterm.js` instance and establishing a stable WebSocket connection to the backend TaskMaster CLI process for basic, real-time data exchange.
### Details:
Implement a React component that encapsulates an `xterm.js` instance using a `ref`. On component mount, initialize the terminal and establish a WebSocket connection. Implement the core data flow: `term.onData` will send user keystrokes to the socket, and `socket.onmessage` will write received data from the backend to the terminal. Handle WebSocket lifecycle events (open, close, error) to ensure connection stability.

## 2. Implement Terminal Aesthetics and Responsive Layout [done]
### Dependencies: 62.1
### Description: Configure the visual appearance of the `xterm.js` terminal to match the project's dark theme and mockups. This includes setting custom colors, fonts, and cursor styles, and ensuring the terminal is fully responsive to its container size.
### Details:
Define and apply a custom theme object to the `xterm.js` instance with colors for background, foreground, cursor, and selection, aligning with Task #52. Set the font family, font size, and a blinking block cursor style. Integrate and configure the `xterm-addon-fit` to make the terminal automatically resize. Use a `ResizeObserver` on the terminal's parent container to call the `fit()` method on dimension changes.

## 3. Implement Command History and Keyboard Shortcuts [done]
### Dependencies: 62.1
### Description: Enhance the user experience by implementing client-side command history navigation and common keyboard shortcuts. This allows users to cycle through previous commands with arrow keys and perform actions like clearing the screen.
### Details:
Implement a client-side buffer (array) to store a history of commands submitted with the Enter key. Use the `xterm.js` `onKey` event handler to capture Up and Down arrow key presses, navigate the history buffer, and update the current input line. Also in `onKey`, implement shortcuts like `Ctrl+L` to call `term.clear()` and `Ctrl+C` to send a special interrupt signal over the WebSocket.

## 4. Develop Multi-Session Tabbed Interface [done]
### Dependencies: 62.1
### Description: Create a higher-level component to manage multiple, independent terminal sessions. This involves building a tabbed interface where users can create, switch between, and close different terminal instances.
### Details:
Develop a `TerminalManager` parent component that manages an array of active sessions in its state. Utilize the atomic tab components from Task #52 for the UI. Each tab will correspond to a unique `Terminal` component instance, each with its own WebSocket connection. Implement logic to add new tabs (creating a new session), switch between tabs (showing/hiding the correct terminal), and close tabs (disposing of the `xterm.js` instance and closing its WebSocket).
